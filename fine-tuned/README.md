# AI 기반 개인 맞춤형 패션 에이전트 (학습 데이터 구축 및 AI 모델 고도화)

사용자의 자연어 요청과 취향·보유 의류·날씨·일정 정보를 분석하여 상황(TPO)에 맞는 맞춤형 코디를 추천하는 **AI 패션 에이전트의 학습 데이터 파이프라인 구축 및 경량 AI 모델(Qwen3.5-4B) 성능 고도화**를 수행한 프로젝트입니다.

* **GitHub 저장소:** <https://github.com/2026-2-projects/ai-fashion-agent>
* **수행 기간:** 2026년 2학기 (팀 프로젝트 / 데이터 및 AI 모델링 파트 전담)

---

## 01. 프로젝트 개요

### 해결하려는 문제
기존의 범용 소형 AI 모델은 패션 추천 서비스를 실제 웹·앱 시스템과 연동할 때 다음과 같은 한계가 있었습니다.
1. **데이터 형식 불일치:** 추천 결과를 정해진 규격(JSON)이 아닌 제각각의 형태로 출력하여, 시스템에서 추천 의류를 자동으로 불러오거나 검증하기 어려웠습니다.
2. **상황 판단(분기) 오류:** 단순한 패션 상식 질문(예: *"검정 니트에 베이지 바지 어울려?"*)에도 불필요하게 복잡한 전체 코디 추천 데이터를 생성하는 비효율이 발생했습니다.

### 프로젝트 목표
* 비정형 자연어 질문을 분석해 서비스 표준 규격에 맞는 **5가지 맞춤형 코디(5 LOOK)**를 안정적으로 생성하는 패션 특화 AI 모델을 구축합니다.
* 질문의 의도에 따라 **외부 정보(날씨·일정·옷장) 조회**와 **즉시 답변**을 스스로 구분하여 처리하도록 학습시킵니다.

### 담당 역할 (김진호 — AI/ML 및 학습 데이터 전담)
* **학습 데이터 설계 및 확장:** 정답 데이터(Gold Data) 80건 설계 및 864건 대규모 학습 데이터셋 확장 구축
* **데이터 품질 검증 및 분할:** 데이터 편향·중복을 걸러내는 자동 검증 리포트 구현 및 학습·검증·평가 데이터 분리
* **AI 모델 추가 학습(Fine-Tuning) 및 평가:** 1차 파일럿(Pilot)과 2차 본 학습(v0.1)을 통해 모델의 형식 준수율 및 상황 판단 정확도 개선
* *(※ 백엔드 및 데이터베이스 연동 파트는 AI 모델의 출력 데이터 형식 정합성을 검토하는 보조 역할로 참여했습니다.)*

## 02. 사용 기술 (Tech Stack)

### 프로그래밍 및 데이터 처리
* **Python** — 학습 데이터 변환, 데이터 무결성 자동 검증, 모델 학습 및 평가 자동화 스크립트 구현
* **JSON / JSONL** — 대화형 AI 학습 데이터 구조화 및 서비스 표준 출력 규격 설계

### AI 모델링 및 실험 환경
* **Qwen3.5-4B (`unsloth/Qwen3.5-4B`)** — 한국어 처리와 도구 호출에 적합한 경량 오픈소스 언어 모델
* **LoRA (파라미터 효율적 미세조정)** — 제한된 GPU 자원으로 모델을 패션 도메인에 특화시키는 추가 학습 기법
* **Google Colab (T4 GPU)** — 클라우드 GPU 기반 모델 학습 및 성능 비교 실험

### 협업 및 연동 지원
* **Git / GitHub** — 브랜치 전략(`main` - `develop` - `feature/*`) 기반 코드 및 실험 결과 버전 관리
* **FastAPI / PostgreSQL** — AI 출력 데이터와 데이터베이스 테이블 간 형식 호환성 검토 지원

## 03. 프로젝트 수행 내용

### 1. 학습 데이터 구축 및 단계적 확장
모델이 '코디 추천'과 '상황별 정보 조회 판단'을 동시에 학습할 수 있도록 두 가지 유형의 데이터를 결합하여 구축했습니다.
* **1단계 (파일럿 검증용, 80건):** 팀원들과 함께 고품질 기준 정답 데이터(코디 추천 50건, 도구 호출 판단 30건)를 구축하여 초기 학습 파이프라인의 작동 여부를 검증했습니다.
* **2단계 (본 학습용 확장, 864건):** 서비스 규격 고도화(3가지 코디 → 5가지 코디 추천)에 맞춰 학습 데이터를 **총 864건(코디 추천 540건, 도구 호출 판단 324건)**으로 대폭 확장했습니다.

### 2. 데이터 품질 검증 및 데이터 누수 방지
학습 데이터의 품질이 곧 모델의 성능으로 직결되므로, 학습 전 자동 검증 절차를 적용했습니다.
* **자동 무결성 검수 (`validation_report.json`):** 스크립트를 통해 고유 ID 중복 여부, 데이터 유형 비율, 4가지 핵심 도구(날씨·일정·옷장·취향)의 호출 분포를 사전 점검하여 데이터 편향을 방지했습니다.
* **엄격한 데이터 분할:** 학습 데이터(864건)와 별도로 **검증용(Validation) 8건, 최종 평가용(Test) 8건**을 완전히 격리하여, 모델이 외운 문제를 다시 푸는 현상(데이터 누수)을 차단했습니다.

### 3. 경량 AI 모델 추가 학습 (Fine-Tuning)
* Google Colab T4 GPU 환경에서 `Qwen3.5-4B` 모델을 대상으로 학습을 진행했습니다.
* 학습 과정에서 오차(Loss) 변화를 모니터링한 결과, 초기 급감 이후 안정적으로 수렴(**평균 학습 오차 0.4376 / 검증 오차 0.4976**)하며 과적합이나 발산 없이 학습이 완료됨을 확인했습니다.

### 4. 동일 평가셋 기반 전후 정량 비교
* 학습에 전혀 사용되지 않은 동일한 테스트 질문 8개(총 24개 세부 평가 항목)를 기준으로, **학습 전 기본 모델(Base)**과 **학습 후 개선 모델(LoRA v0.1)**의 결과를 객관적으로 비교했습니다.

## 04. 프로젝트 결과

### 1. 핵심 정량 성과 (자동 평가 24개 항목 기준)
864건의 확장 데이터로 학습한 결과, 서비스 연동에 필수적인 **모든 구조적 평가 항목에서 100% 통과율**을 달성했습니다.

| 평가 항목 | 기본 모델 (학습 전) | 개선 모델 (LoRA v0.1) | 개선 효과 |
| :--- | :---: | :---: | :--- |
| **코디 번호(ID) 형식 정확도** | 60.0% | **100.0%** | **+40.0%p 향상** (1~5 정수 통일) |
| **첫 행동(도구 호출/직접 답변) 정확도** | 66.7% | **100.0%** | **+33.3%p 향상** |
| **데이터 형식(JSON) 및 5가지 코디 규격 준수** | 유지 | **100.0%** | 시스템 자동 연동 기준 충족 |
| **전체 자동 평가 통과율** | **87.5% (21/24)** | **100.0% (24/24)** | **+12.5%p 향상 (전 항목 통과)** |

### 2. 실제 응답 개선 사례
* **사례 1 — 시스템 연동 가능한 표준 데이터 출력 (`TEST-001`, `TEST-005`)**
  * **학습 전:** 코디 번호를 `"look_001"`, `"interview_classic_navy"`처럼 임의의 문자로 출력하여 시스템에서 자동으로 인식할 수 없었습니다.
  * **학습 후:** 약속된 규격인 `1, 2, 3, 4, 5` 정수 형태와 정해진 추천 순서(취향 최적 + 새로운 스타일 제안)를 100% 정확하게 지켜 출력했습니다.
* **사례 2 — 질문 의도에 맞는 효율적 응답 분기 (`TEST-007`)**
  * **학습 전:** 날씨나 옷장 조회가 필요 없는 단순 패션 질문에도 불필요하게 5가지 코디 전체 데이터(JSON)를 생성했습니다.
  * **학습 후:** 외부 도구 조회가 불필요한 상황임을 스스로 판단(`direct_answer`)하여 간결하고 자연스러운 텍스트 답변만 반환했습니다.

## 05. 문제 해결 경험 및 향후 개선 방향

### 1. 파일럿 단계의 데이터 문법 오류 해결
* **발생한 문제:** 초기 80건 데이터로 진행한 1차 파일럿 테스트에서는 전체 통과율이 87.5%(7/8)에 머물렀으며, 특정 테스트(`FR-015`)에서 불필요한 특수문자(`-`)가 섞여 데이터 파싱(해석) 자체가 실패하는 오류가 발생했습니다.
* **해결 방법:** 데이터 부족으로 인한 출력 불안정성을 원인으로 진단하고, 학습 데이터를 864건으로 10배 이상 확장하면서 출력 스키마 검증 기준을 강화하여 재학습을 진행했습니다.
* **개선 결과:** 2차 학습(`LoRA v0.1`)에서는 데이터 문법 오류가 완전히 사라져 **JSON 유효성 100%**를 달성했습니다.

### 2. 정성적 문장 품질 한계 도출 및 고도화 계획 (`v0.2`)
* **한계점 분석:** 자동 평가 100% 달성은 '데이터 형식과 규칙을 완벽히 지켰다'는 의미이며, 실제 추천 사유 문장을 검수한 결과 일부 단어 반복(예: *"차분한 차분한"*)이나 간헐적인 오탈자가 남아 있음을 확인했습니다.
* **향후 개선 방향:** 현재 모델(`v0.1`)을 앱 통합용 기준 모델로 확정하여 백엔드 연동에 활용하고, 향후 실제 서비스 테스트에서 수집되는 실패 사례를 사람이 직접 검수·수정한 데이터(HITL)로 구축해 **`v0.2` 재학습**을 진행할 계획입니다.
